## 문제 상황

- 프로젝트 빌드 시간이 1분 30초를 초과
- CI/CD 파이프라인에서 병목 발생

## 원인 분석

빌드 로그 확인 결과

```
info - Disabled SWC as replacement for Babel because of custom Babel configuration ".babelrc"
```

**주요 문제점:**

- .babelrc 파일로 인한 SWC 비활성화
- 738MB 크기의 node\_modules
- 1MB 이상의 대용량 번들
- 200개 이상 페이지의 SSR 설정

## 해결 과정

### 1. SWC 컴파일러 활성화

```
rm -f .babelrc
```

```
// next.config.js
const nextConfig = {
  // SWC 강제 활성화
  swcMinify: true,
  // 빌드 최적화
  experimental: {
    forceSwcTransforms: true,
  },
  // 컴파일러 최적화
  compiler: {
    removeConsole: process.env.NODE_ENV === "production",
  },
};
```

### 2. JSX 문법 오류 수정

- SWC 전환 후 문법 오류 발견하여 수정

{% raw %}
```
// 수정 전
<Box style={{ margin: "0px 20px" }}>-></Box>

// 수정 후
<Box style={{ margin: "0px 20px" }}>→</Box>
```
{% endraw %}

### 3. 번들 최적화

- 웹팩 청크 분할 설정

```
webpack: (config, { dev }) => {
  if (!dev) {
    config.optimization = {
      ...config.optimization,
      splitChunks: {
        chunks: 'all',
        cacheGroups: {
          vendor: {
            test: /[\\\\\\\\/]node_modules[\\\\\\\\/]/,
            name: 'vendors',
            priority: 10,
          },
          mui: {
            test: /[\\\\\\\\/]node_modules[\\\\\\\\/]@material-ui[\\\\\\\\/]/,
            name: 'mui',
            priority: 20,
          },
        },
      },
    };
  }
}
```

&nbsp;

### ETC. 추가 개선사항

- 번들 분석 도구 추가

```
npm install --save-dev @next/bundle-analyzer
```

지속적 모니터링을 위한 npm run analyze 명령어 지원.

## 요약

```shell
1. **SWC 컴파일러 활성화**
   - .babelrc 파일 제거
   - next.config.js에 forceSwcTransforms 적용
   - JSX 문법 오류 수정

2. **번들 최적화**
   - vendor/mui 청크 분리
   - 프로덕션 console.log 제거
   - 코드 스플리팅 개선
```
